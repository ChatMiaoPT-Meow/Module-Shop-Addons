# Module-Shop-Stock 审查与 2.0 设计

> 审查对象：`Module-Shop-Stock`（1293 行 Java，10 个类）
> 依赖：MC 1.21.1 / NeoForge 21.1.248 / Module-Shop 1.0.5.1（API 1.2.0）/ AtomLib 0.1.0-beta
> 内容区可用尺寸：**280 × 182 GUI px**（面板 400×218，侧栏 104，顶栏 28）

---

## 一、审查

### 1.1 结构

当前是干净的四层，职责没有串：

| 层 | 类 | 职责 |
| --- | --- | --- |
| 定义 | `StockMarket` | 4 只股票的静态常量 |
| 存档 | `StockMarketSavedData` | 行情、历史点、持仓（`data/module_shop_stock.dat`） |
| 服务端 | `StockMarketManager` | 价格演化、交易复核、结算、广播 |
| 客户端 | `StockMarketState` / `StockMarketPage` / `StockMarketFallbackScreen` | 快照缓存、AtomLib 页面、原版回退界面 |

协议只有一对 payload（`Request` / `Response`），内部用 `type` 字符串分路由。资金全部走 `ModuleShopApi.economy()`，没有绕过经济系统自己改余额——这点做得对，也是后续加功能的前提。

### 1.2 问题清单

按「会不会挡住新功能」排序。

**A. 结构性障碍（做「管理员加股」必须先解决）**

1. `StockMarket.STOCKS` 是 `List.of(...)` 常量（`StockMarket.java:11`），同时被服务端和客户端引用。客户端有三处按它过滤或建控件：
   - `StockMarketState.java:209` 用 `StockMarket.find()` 过滤行情，服务端新增的股票会被客户端**直接丢掉**；
   - `StockMarketPage.java:40` 在构造函数里按常量建标签按钮，新股票不会出现；
   - `StockMarketFallbackScreen.java:26` 同样遍历常量。
2. `StockMarketSavedData.load()` 对未知 symbol 的行情和持仓一律 `continue`（`:70`、`:91`）。管理员删股再建同代码的股票，**旧持仓凭空消失**；这也是存档层面的数据丢失点。
3. 股票名是翻译键（`stock.module_shop_stock.farm`），玩家自定义的股票没有对应语言文件，只能显示 symbol。

**B. 行情与带宽**

4. 历史只有 32 个价格点（`HISTORY_LIMIT`，`:19`），30 秒一点 = 16 分钟，且只有收盘价，画不出 K 线、成交量和时间轴。
5. `broadcastMarket()` 每 30 秒向**全服在线玩家**发全部行情（含 history 数组，`:216`）；客户端页面又每 5 秒主动 `requestSnapshot()`（`StockMarketPage.java:82`）。股票从 4 只涨到 20 只、历史点从 32 涨到 180 之后，这个量会到每包几十 KB。现在不做分包，后面加不动。
6. 每次交易先 `result`、再 `broadcastMarket`、再 `sendSnapshot`（`:116`），同一份行情发了三遍。

**C. 交易语义**

7. 没有手续费。`total = price × qty` 直接结算（`:102`），经济系统没有任何磨损。
8. 买入不是原子的：先 `take()` 扣钱（`:127`），再改持仓（`:133`）。中间抛异常就是「钱扣了、股没到」。当前代码路径短、风险低，但加手续费和限价单冻结后，多步结算必须一次性算完再落账。
9. 卖出忽略 `add()` 的返回值（`:148`）。上游 `add` 在余额接近上限时会把装不下的部分转成金钱邮件并返回**实际入账额**，附属仍然按 `total` 提示「收入 X」。总额没错（现金 + 邮件 = total），但玩家看到的和实际到账形式不一致。已确认上游 `LIMIT_EXCEEDED` 分支本身不发邮件，所以附属补发全额邮件**不会重复**，这段逻辑是对的。
10. `sell()` 里 `data.position()` 会为任意 symbol 建空仓（`:143`），包括已下架的股票。`save()` 会过滤掉，但内存里会留脏数据。
11. 没有任何「停牌 / 涨跌停 / 交易时段」概念。管理员想临时冻结一只股票只能关掉全局开关。

**D. 细节与健壮性**

12. 计时用 `System.currentTimeMillis()`（`:32`），服务器卡顿或挂起后不会补算，价格时间轴和真实时间会漂。
13. `quote()` 里做 clamp 并 `revision++` + `setDirty()`（`:183`），副作用藏在读方法里；`quotesTag()` 每次广播都调用它。
14. `reset()` 没有重置 `maxTradeQuantity` 和 `enabled`（`StockMarketState.java:50`），切换服务器后会残留上一台的配置（5 秒后快照会修正，属于短暂错值）。
15. `clamp()` 在 `minPrice` 配得比 `basePrice × 4` 还大时，会把所有股票钉死在上限（`max = min`），行为可预期但没有提示。
16. 左侧列表没有滚动和裁剪。4 只股票刚好，第 5 只就会画进图表区域。
17. `StockMarketPage.render()` 正常分支直接 `this.quantity.bounds(...)`，没判 `init` 是否执行过。

**E. 构建**

18. 主仓库有 `module_shop-1.0.5.1-api.jar`，但没有 `module_shop-1.0.5.1.jar`，`runClient` 会退回到 `1.0.5` 完整包。API 一致时没问题，改 API 后要记得补构建，否则本地运行时会出现「编译通过、运行时缺方法」。

### 1.3 结论

地基是好的，资金与存档都守住了「服务端权威」。**真正要改的不是补几个功能，而是把「股票定义」从编译期常量搬进存档**——这一步做完，加股、删股、改名、加行业、动态 UI 都是自然延伸；不做这一步，任何新功能都只能在 4 只股票上打补丁。

## 二、设计目标

**做**
- 股票定义运行时可增删改，管理员有独立权限，改动可审计、可回滚。
- 行情从「32 个点」升级为 OHLCV 柱，能画 K 线、成交量、时间轴。
- 交易从「只有市价单」升级为市价 + 限价委托，带手续费、停牌、交易时段。
- 界面在 280×182 里做出信息密度：多视图、可滚动、可搜索、可自选。

**不做**
- 不做真实证券行情对接、不做多人撮合的订单簿（没有对手盘，用合成流动性）。
- 不改主仓库 Module-Shop 的任何代码，只依赖现有公共 API 1.2。
- 不做跨服同步（单服存档模型不变）。

## 三、数据模型

存档从 v1 升到 v2，`dataVersion` 落盘，旧档自动迁移。

```
StockMarketSavedData
├─ dataVersion = 2
├─ revision                      // 用于客户端判重
├─ defs:  Map<String, StockDef>  // 定义（替代静态常量）
├─ quotes: Map<String, Quote>    // 行情
├─ positions: Map<UUID, Map<String, Position>>   // quantity, locked, cost
├─ orders: List<Order>           // 限价委托
├─ watchlist: Map<UUID, List<String>>            // 自选，最多 32
├─ fund: long                    // 手续费池（分红来源）
├─ dayKey: long                  // 当日分隔（epoch day）
└─ audit: 环形缓冲 200 条
```

**StockDef**（可变记录，管理员可编辑字段）

| 字段 | 说明 |
| --- | --- |
| `symbol` | 2–8 位 `A-Z0-9`，创建后不可改 |
| `name` | 显示名，玩家自定义直接存字符串 |
| `nameKey` | 内置股票的翻译键，`name` 为空时回退到它 |
| `sector` | 行业标签，用于列表小标签与筛选，自由字符串（建议 2–4 字） |
| `basePrice` | 基准价，决定波动中枢与价格带 |
| `volatility` | 单 tick 高斯波动率（0.005–0.15） |
| `float` | 流通盘（可供交易的股数），决定市值、冲击成本与单人持仓上限 |
| `enabled` | 是否可交易 |
| `halted` | 是否停牌（价格冻结、委托不撮合） |
| `prevClose` / `dayOpen` | 日切时写入，用于涨跌幅与当日盈亏 |

**Quote**

```
price, prevPrice, dayOpen, dayHigh, dayLow,
volume,                 // 当日成交量（股）
bars: Bar[]             // 最近 N 根 1 分钟柱
```

**Bar**：`t(epochSecond), open, high, low, close, volume`。默认 1 分钟一根，保留 180 根（3 小时）；5m / 15m 由客户端本地聚合，不额外存。

**Order**：`id(long), owner, symbol, side, price, qty, filled, createdAt, expireAt, state`。买入冻结资金、卖出冻结股票（`Position.locked`）。

## 四、协议

通道版本从 `"1"` 升到 `"2"`。旧版客户端连新服直接握手失败，比「连上但只看到 4 只股票」更容易排查；这个包本来就是 BOTH 侧必装。

四类下行包，按「变化频率」拆开，这是解决带宽的关键：

| 包 | 触发 | 内容 | 估算 |
| --- | --- | --- | --- |
| `snapshot` | 打开界面 / 交易后 / 定义变更 | defs + 我的持仓 + 我的委托 + 自选 + 现金 + 指数 + 基金 + admin 标记 + 市场状态 | ~1–3 KB |
| `market` | 每个价格 tick（默认 30s） | 仅 `symbol / price / prev / volume / revision` | ~30 B × N |
| `chart` | 切股票 / 切周期 / 每 60s | 单只股票的 bars | ~2 KB |
| `result` | 交易 / 管理动作回执 | `nonce, ok, message, args` | 固定 |

上行只有 `snapshot`、`trade`、`cancel`、`chart`、`admin` 五种。所有 `admin` 动作在服务端**再验一次** `hasPermissions(2)`，客户端的按钮可见性只是 UI，不是权限。

## 五、服务端

### 5.1 价格引擎

每次更新把四项叠加，再叠均值回归：

| 项 | 作用 |
| --- | --- |
| 学生 t 分布（df=4） | 替代高斯噪声，极端涨跌比正态更常见 |
| `volState`（EWMA） | 波动率聚集：近期振幅大，接下来一段就更躁动 |
| `momentum` | 缓慢衰减的趋势项，让价格走出一段行情而不是纯噪声 |
| 跳变 | 约 0.9% 概率叠加 0.8–3 倍单期冲击 |

单次更新的总变动夹在 ±12%，避免一根柱子翻倍；再叠加向 `basePrice` 的均值回归与新闻加成。

**价格在对数空间里演化，并补上 `+σ²/2` 的伊藤项。** 这一步是必需的：直接在价格上乘 `(1+move)` 时，
高波动会带来几何拖累（波动越大，期望越低），跑一段时间所有股票都会一起阴跌——第一版就是这个毛病。
全局倍率 `volatilityMultiplier`（默认 1.2）把整套波动一起放大，管理员按股票调 `volatility` 还能再分层。
用 400 组 2 小时路径模拟校准过：单次波动 3.2%–4.6%，FARM 两小时落在 −19%…+24%，VOID 落在 −51%…+59%，中位数接近 0。

- 用 `dayKey` 做日切：`prevClose = price`，重置 `dayOpen/dayHigh/dayLow/volume`。
- 价格只受「长期价格带」约束：`basePrice/4 … basePrice ×4` 再与配置的 `minPrice / maxPrice` 取交集。
  没有日内涨跌停，也没有熔断；要冻结一只股票用「停牌」，要冻结全市场用全局开关。
- 每次更新按波动幅度生成一笔**模拟成交量**（`depth × 3%` 为基础），所以每只股票都有成交量柱，
  不会出现「只有交易过的股票才有那一栏」。

### 5.2 撮合（限价单）

合成流动性模型，不需要对手盘：

1. 买单挂单价 ≥ 市价 → 以**市价**成交（对买家更优，差价退回冻结）。
2. 卖单挂单价 ≤ 市价 → 以市价成交。
3. 每次成交按 `qty / depth` 施加冲击，与现有 `applyImpact` 同一个模型。
4. 过期（默认 1 真实日）自动撤单、退款、通知。
5. 每人最多 8 笔挂单；下单前校验冻结额，冻结即扣款，避免超买。

### 5.3 手续费与基金

- 买卖双边收 `feeBps`（默认 30 = 0.3%），`minFee` 默认 1，向上取整。
- 手续费进入 `fund`；`/shopstock dividend` 按持仓市值占比把基金分给持仓玩家，走 `economy.add()`，记录审计。
- 基金余额在界面顶栏可见，管理员能看到池子有多大。

### 5.4 管理端

**只通过界面操作，不注册命令。** 管理台是页面里的第五个页签（`snapshot.admin == false` 时既不渲染也不发包），
动作全部走同一个 `AdminService.apply(player, action, payload)`，服务端每个动作都重新校验 `hasPermissions(2)`
与参数范围——客户端的按钮可见性只当提示。

| 页签 | 作用 |
| --- | --- |
| 股票 | 列表（代码 / 名称 / 停牌与下架标记 / 持仓人数 / 现价），选中后可编辑、停牌、上下架、删除、分红 |
| 新建 | 代码、名称、行业、基准价、波动率、流通盘六个字段，同时承担「编辑」 |
| 消息 | 给某只股票发一条 ±30% 以内的事件，立即跳空并抬高短期波动 |
| 审计 | 最近 20 条管理操作 |

- 校验：symbol 2–8 位 `A-Z0-9` 且唯一，名称 1–24 字，行业 ≤8 字，基准价 1–1e6，波动 0.002–0.15，流通盘 10 万–2000 万。
- 删除：有持仓或挂单时，界面第一次点击只把按钮变成「确认删」，第二次才发 `force=true`；服务端再复核一次人数与挂单数。
  强制删除会撤销该股票全部委托并退款，持仓按现价清算给持有人。
- 停牌与下架都会撤销该股票的未成交委托并退回冻结；下架后只能卖不能买。
- 审计：内存环形 200 条 + `logs/module_shop_stock-admin.log`。

### 5.5 开服预置（可选）

`config/module_shop_stock/stocks.json` 在服务器启动时自动合并：只新增、只更新参数，**不删除**——
配置文件里删掉一行不会让玩家持仓蒸发。没有这个文件也能跑，界面里加股同样有效。

```json
[
  {"symbol": "GOLD", "name": "金库", "sector": "金融", "base": 320, "vol": 0.03, "depth": 5000}
]
```

### 5.6 自动新闻

`NewsService` 每 `newsIntervalMinutes`（默认 10 分钟，实际 0.6–1.4 倍随机）挑一条消息，共 **100 条**模板：

| 范围 | 条数 | 抽中概率 | 影响 |
| --- | --- | --- | --- |
| 单只股票 | 60（30 利好 / 30 利空） | 60% | ±1% … ±15% |
| 板块 | 25（13 利好 / 12 利空） | 25% | 同行业全部股票 ±1% … ±8% |
| 全市场 | 15（8 利好 / 7 利空） | 15% | 所有上市股票 ±1% … ±3% |

题材覆盖订单、产能、勘探、事故、监管、人事、研发、融资、渠道、物流、天气、谣言十二类；
文案在语言文件的 `news.*`，权重与幅度在 `NewsService.TEMPLATES` 一行一条。

- 文案存翻译键，股票名作为参数下发，客户端按自己的语言渲染；
- 触发后立即按百分比推动价格，并把 `newsBoost` 抬高到 2.5 倍，随后逐次衰减——新闻之后的几根柱子明显更剧烈；
- 同时发两路：聊天栏 `【快讯】…`、界面顶栏的圆点快讯（18 秒后让位回指数 / 现金 / 资产）；
- 管理台的手写消息走同一条通道，只是文案是字面量。

### 5.7 迁移

`load()` 读到 v1：用当前股票池填充 `defs`（`nameKey` 保留原翻译键），把 `history` 的 32 个价格点转成 32 根合成柱（时间倒推、OHLC 全等、volume 0），持仓按 symbol 保留——**包括 defs 里没有的**。

v2 存档升级到 2.1 时走 `seedDefaults()`：把股票池里**缺失的**补进来（老存档从 4 只变 20 只），已有定义原样保留，
并用 `seeded` 标记保证只补一次——管理员删掉的股票不会在重启后自己长回来。

**为 50 人规模做的三道约束**

1. **冲击成本按流通盘算，走平方根定律**：`impact = 0.08 × √(成交股数 / 流通盘)`。
   下单量翻四倍，冲击只翻一倍——「砸十倍的钱」推不出十倍的涨幅。
2. **单人持仓上限 = 4% 流通盘**（`positionLimitPercent`）。这一条是硬约束，和玩家的钱包厚度无关：
   再有钱也只能买到 4%，对单只股票的最大影响约 +11.7%（分批买入的复利冲击合计）。
   买入推高、卖出砸低，来回一趟是亏的，操纵没有收益。
3. **模拟回放校准**：50 人各 100 万、2 小时随机交易，指数中位 **+2.2%**，5–95% 区间 **−6.4% ~ +12.4%**。
   玩家整体行为只能推动大盘几个百分点，真正的大幅波动来自新闻事件。

### 5.9 做空

界面上是名称行右侧的 `多 | 空` 切换，切到空头后下单区变成 `开空 / 平空`，快捷量变成 `最大 / 全平`。
市价与限价都支持：开空挂单挂在高位、平空挂单挂在低位，和做多的限价单走同一套撮合。

| 动作 | 资金流 |
| --- | --- |
| 开空 q 股 @ p | 冻结保证金 `p × q × 100%`（`shortMarginPercent`），记入空头持仓 |
| 平空 q 股 @ p₂ | 退回 `保证金份额 + (开空均价 − p₂) × q`，亏损以该笔保证金为限 |
| 强制平仓 | 权益（保证金 + 浮盈）跌破保证金的 20% 时按现价结清，退回剩余权益 |

限价单的冻结物按方向区分：开空挂单冻结**现金保证金**（按限价算，成交价更优时退回差额、更差时补扣），
平空挂单冻结**空头股数**（`shortLocked`），避免同一批空头被多张单重复平掉。撤单、过期、下架、删股都走同一个 `release()`。

- 强平线对应价格：100% 保证金、20% 维持比例时约 **+80%**，也就是价格翻倍前一定已经被平掉；
- 单人做空上限与做多共用 4% 流通盘，方向分开计；
- 下市 / 删除股票时，空头按现价结清并退回剩余保证金，不会吞掉冻结的钱；
- 保证金比例与强平线分别由 `shortMarginPercent`、`shortMaintenancePercent` 配置。

盈利上限是 100%（价格归零），亏损上限是保证金，风险对称——没有杠杆，也就不会出现穿仓负债。


### 5.10 做市商与盘口

价格不再等于成交价。中间价（`price`，图表与涨跌幅用它）由随机过程决定，做市商围绕它双边报价：

```
half   = clamp(volatility × 0.18, 0.15%, 2%)        // 波动越大价差越宽
skew   = clamp(库存 / 流通盘 × 2.5, ±1.2%)           // 库存多就整体压价
bid    = mid × (1 − half − skew)
ask    = max(bid + 1, mid × (1 + half − skew))
深度    = 流通盘 × 0.25% × (1 + 0.8 × 档位)
```

- **市价买入成交在卖一，市价卖出成交在买一**；做空开仓按买一、平空按卖一。
- 限价单的穿越判断也改成对买一/卖一：买单挂价 ≥ 卖一才成交，且按卖一成交（对玩家更有利）。
- 每次成交让做市商库存反向变动，库存再按每轮 1.5% 衰减。于是大额买入之后报价会先被顶高、再慢慢回到中间价——这就是真实盘面的「冲击后回补」。
- 盘口页显示卖方五档在上、买方五档在下，前五档来自做市商深度曲线，叠加玩家挂在这一档的委托，背景色条按占最大档的比例铺开。

因为价格是整数，最低买卖价差是 1 个货币单位：87 的股票是 1.15%，28 的股票是 3.6%。
这跟现实里「便宜股相对价差更宽」是一致的。

### 6.2 交互原则

- 所有金额来自服务端快照，客户端只做展示与预估；预估金额按现价 × 数量，实际以回执为准。
- 提交期间按钮禁用并显示「提交中…」，`nonce` 对账沿用现有机制；超时 5 秒自动解锁。
- 价格变动导致回执失败时，不弹窗，只在底栏用一行红字提示「价格已经变化，请按最新价格重新提交」。
- 撤单与删股都要求二次确认（按钮文案变成「确认」/「确认删」，3–4 秒内有效），避免误触。
- 管理员入口固定为最后一个 tab，`snapshot.admin == false` 时既不渲染，也不发任何管理包。

### 6.3 管理台

四个子页签：`股票`（列表 + 编辑/停牌/下架/删除/分红）、`新建`（同时承担编辑）、`消息`（事件）、`审计`。
选中行用强调色底，动作按钮排在列表下方一行五个。

原版回退界面（AtomLib 不可用）只保留：分页股票列表、市价买卖、持仓、指数。限价单、K 线、管理台在回退界面里不做——非 Windows 平台本来就只是兜底。

## 八、风险与取舍

| 风险 | 处理 |
| --- | --- |
| 存档迁移出错导致持仓丢失 | 迁移只做「补 defs + 转 bars」，持仓原样保留；启动时检测到 v1 自动备份成 `module_shop_stock.dat.v1.bak` |
| 限价单冻结导致玩家「钱不见」 | 冻结即扣款、撤单即退，委托页显示「已成交 / 挂单量」；买入成交价优于限价时差额自动退回 |
| 手续费被玩家视为「抽水」 | 默认 0.3%，基金余额公开可见并可按持仓分红；`feeBps` 设 0 即全免 |
| 分包后客户端状态不一致 | `revision` 单调递增，旧 `revision` 的 `market` 包直接丢弃 |
| 管理台误操作删股 | 有持仓或挂单时按钮变成「确认删」，二次点击才发送；服务端复核人数与挂单数后强制清算 |
| 上游 `add` 在邮箱满时可能丢差额 | 卖出前不预判；`credit` 遇 `LIMIT_EXCEEDED` 补发金钱邮件，邮件也满时整笔不落账并在回执提示 |

## 九、已确定的取舍

1. **范围**：P0–P3 全做。
2. **限价单**：做。市价 + 限价 + 撮合 + 撤单 + 冻结。
3. **管理入口**：只走 GUI。不注册命令，因此**加股必须进游戏**；控制台只能通过 `stocks.json` 预置。

## 十、验收清单

进游戏后按顺序过一遍：

1. **旧档升级**：用旧存档启动，`world/data/module_shop_stock.dat.v1.bak` 应出现；进商店看持仓是否还在、股票池是否补到 20 只。
2. **加股**：管理 → 新建，填 `GOLD / 金库 / 金融 / 320 / 0.03 / 5000`，保存后行情页立刻出现 GOLD，基准价 320，K 线是 24 根平价柱。
3. **交易**：市价买 10 股，看现金减少 = 成交额 + 手续费，持仓均价含手续费；卖出 5 股，现金增加 = 成交额 − 手续费。
4. **限价**：切到限价，价格填低于现价，买入 → 现金被冻结、委托页出现挂单；撤单 → 现金全额退回。
5. **停牌 / 下架**：管理 → 停牌，行情页该股票变金色、下单按钮禁用、未成交委托被撤销并退款。
6. **删除**：给 GOLD 建仓后直接删 → 第一次点击只改按钮文案，第二次才清算并删除，聊天栏收到清算到账。
7. **分红**：成交几笔后管理 → 分红，基金清零，持仓者的余额增加，审计多一条 `dividend`。
8. **新闻**：消息页填 `GOLD / 8 / 发现新矿脉`，全服聊天收到广播，GOLD 立刻跳涨 8%，随后几根 K 线波动明显变大。
9. **自动新闻**：把 `newsIntervalMinutes` 临时改成 1，等一两分钟——聊天栏应出现 `【快讯】…`，顶栏变成圆点快讯，
   被点名的股票立刻跳空，随后几根柱子波动明显放大。
10. **成交量**：不交易任何股票，K 线下方也应有一排成交量柱（模拟成交），不再是空白。
11. **缩放**：鼠标移到盘面上滚轮，蜡烛变粗 / 变细，向左看到更早的行情；缩到最小时不应出现半根柱子。
12. **回退界面**：非 Windows 或 AtomLib 缺失时，回退界面仍能分页选股与市价买卖。
