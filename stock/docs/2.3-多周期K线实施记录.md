# 2.3 多周期 K 线实施记录（阶段 G）

分支 `stock-2.3-kline`。设计依据：`盘面与技术面方案-2026-11-10.md` §1.1–1.2、§7、§8.1、§8.3、§8.4。
本阶段**只改展示、存档与同步，不改价格过程**；价格模型由另一分支重写，两边的接缝见文末「合并注意」。

## 1. 数据结构（纯 Java，包 `market/bars/`）

| 类 | 职责 |
| --- | --- |
| `BarPeriod` | 六个周期枚举 `M1/M5/M15/H1/D1/W1`；协议/配置短名 `1m/5m/15m/60m/1d/1w`（`parse` 兼容别名 `1h`，缺省或无法识别按 1m）；`start(epochSec, sourceSeconds, zone)` 计算包含该时刻的柱起点 |
| `BarSeries` | 定长环形缓冲，`AbstractList<Bar>`（旧代码 `bars.get/size/add/clear` 照用），满了追加丢最老的；`setLimit` 调小立刻丢头；`prepend` 接更早历史 |
| `BarAggregator` | 每只股票一个，持有 6 个 `BarSeries`；`sample(...)`/`trade(...)` 每次最多 6 次 O(1) 更新；`backfillFromSource()` 从 1m 回填空的粗周期 |
| `BarCodec` | 一个周期的紧凑打包（见 §2），纯数组，不依赖 NBT |
| `BarHistorySeeder` | 日/周风格化种子（见 §3） |

要点：

- 只有一份价格过程。每次采样/成交的增量（价、影线、量）同时落到 6 个周期各自的末根上，等价于「1m 柱 fold 进粗周期末根」，粗周期末根始终含未收盘的 1m。不回扫历史。
- 新柱开盘价 = 该周期上一根收盘；某周期还没有柱时用 `firstOpen`（沿用旧逻辑 `prevPrice`）。
- 时间对齐：1m 对齐 `barSeconds`（源周期，默认 60，改成 30 则源 30s，5m 仍按 300s）；5m/15m/60m 对齐服务器本地时区的整点；日 = 本地零点；周 = 本地周一零点（ISO 周）。**不做日历压缩**，日线沿用 `rollDayIfNeeded` 同一个自然日钟。日/周柱 `time` = 该段开盘时刻。
- `Quote.bars` 现在是 1m 的 `BarSeries`（仍是 `List<Bar>`），新增 `Quote.book`（`BarAggregator`）。`Bar` 新增 `seeded` 标记，被真实采样/成交触碰（`touch`）即清除。
- 根数上限：`BarAggregator` 构造时各周期上限放到 `maxLimit`（防读档被截），每个行情 tick 由 `StockMarketConfig.syncBarLimits` 同步到配置值。

## 2. 存档格式与兼容

`quotes[i]` 下新增 `kline`（Compound），每个有数据的周期一个子键（键名即周期短名）：

```
kline.<1m|5m|15m|60m|1d|1w> {
  t0:  long      首根时间（epoch 秒）
  dt:  int[n]    与上一根的时间差（秒，首根 0）
  p:   int[4n]   n 个开 + n 个高 + n 个低 + n 个收（价格上限 1e8，落在 int 内，超出夹紧）
  v:   long[n]   成交量
  f:   byte[n]   bit0 = seeded，仅当本周期存在种子柱时才写
}
```

每根约 28 字节（NBT 写盘还会 gzip），按默认根数 24 股总计约 2.7MB 未压缩。

读档：

- 有 `kline`：直接读入；残缺数组按最短对齐，不抛异常。
- 没有 `kline`（2.2 及更早）：旧 `bars` 列表读成 1m，粗周期丢弃重建（`finishBars`：从 1m 聚合回填，再给日/周补种子）。
- 连 `bars` 也没有：沿用旧 `seedBars`（72 根 1m），整体标 seeded，再回填 + 种子。
- 保存时只写 `kline`，**不再写旧 `bars`**。降级回 2.2 会读不到 K 线（会重新生成种子），其它存档数据不受影响。
- 旧 `migrateFromV1` 路径同样走 `finishBars`。

## 3. 历史种子（`BarHistorySeeder`）

- 日线不足 60 根时才补，且只补到现有最老日柱之前（没有日柱则补到「昨天」）；周线由更长（182 天）的日路径聚合，保证日/周同源，剔除与现有周柱重叠的那一周。
- 路径：从锚点（昨日收盘 / 最老日柱开盘）**反向**生成的有界游走：对数价 OU 回归个股基准价，单日涨跌夹紧 ±12%，整体不离开基准的 0.5～2 倍；日 σ 由 `volatility*0.30` 夹在 0.8%～4%；种子固定为 `symbol.hashCode()`，同一股票重复生成结果一致。
- 柱上打 `seeded`：客户端淡显并在图区右上角标「模拟」。**种子不是真实行情，也不应拿来做技术面验收**。
- **接新价格模型：只需替换 `generateDailyPath` 这一处**（或让它调用新模型的日尺度采样），签名与 `seedCoarse` 调用点不用动。

## 4. 协议变化（`CHANNEL_VERSION` 仍为 "3"，未 +1）

不 +1 的理由：新旧两端字段互相忽略，旧客户端（不传 `period`）按 1m 照常工作，+1 反而会把旧客户端挡在门外。

- 请求 `type=chart` 新增 `period`（字符串短名），缺省按 1m。
- 回包 `chart` 新增：`period`、`limit`（该周期服务端上限）、`tz`（服务器本地时区偏移秒）、`sd`（byte[]，种子标记，仅有种子柱时才带）。`t/o/h/l/c/v` 仍是 long[]，只含所请求周期。
- 节流：同 (symbol, period) 全量 500ms；换股/换周期不受此限；任何请求之间最小 80ms。
- 看图订阅：`ChartService` 记住每位玩家当前 `(symbol, period)`，行情广播 `market` 里只给这些人附 `cd`（`symbol/period/limit/t/o/h/l/c/v[/sd]`，最近两根柱，上一根可能被成交补过）；45 秒没有 chart 请求就停止附带，未看图者不发。客户端每 15 秒兜底重拉一次全量。
- 客户端发现回包不带 `period`（2.3 以前的服务端）→ `StockMarketState.legacyServer = true`，周期芯片置灰，固定 1m。

## 5. UI 变化（280×182，没有挤动下单区/盘口）

- `QuoteView` 中栏第一行：左侧股票名（+ 空间够时的代码，**行业标签被去掉**以腾位置），右侧 6 个周期芯片 `1分 5分 15分 1时 日 周`（宽度由文字宽度算，约 90px，当前周期高亮）。K 线区高度、价格行、下单区尺寸与坐标均未变。
- 切周期：立即请求 chart（`chartAt=0`），缩放重置为该周期默认（分钟 32 根，日/周 60 根），平移回到最新；新周期数据到达前显示「正在读取 K 线…」（避免错周期时间轴误导）。
- `ChartRenderer`：MA 改为 MA5/MA10/MA20（客户端按收盘价现算，颜色分别 gold / accent / text2）；时间轴分钟与小时周期 `HH:mm`，跨日时两端带 `MM-dd`；日/周 `MM-dd`；一律按服务端时区（`tz`，旧服务端回退客户端时区）；悬停时间标签分钟周期显示 `MM-dd HH:mm`；种子柱 38% 透明度 + 右上角「模拟」标签；悬停 OHLC 文案改走语言键。
- `StockMarketFallbackScreen`（原版回退界面）本来就没有 K 线图，**未改动**；它不依赖任何被改动的 API，编译通过。
- 语言键（中英）：`gui.stock.period.{1m,5m,15m,60m,1d,1w}`、`gui.stock.chart_seeded`、`gui.stock.chart_ohlc`。

## 9. 游戏内需验证点

1. 旧存档（2.2）进服：1m 保留，5m/15m/1h 有回填，日线约 60 根、周线约 26 周，种子柱淡显并有「模拟」标签；存一次再重启，数据不变。
2. 全新存档：六个周期都有图；放置一段时间后，真实采样柱不再淡显（`seeded` 被清除）。
3. 周期芯片：点击切换、选中高亮、鼠标悬停；中栏名称较长/语言切英文时芯片不被挤出、不与名称重叠；不同界面缩放/皮肤下布局。
4. 切周期立即出图（不超过约 0.3s），无错周期闪烁；快速连点各芯片不卡死、最终显示最后点的周期。
5. 时间轴：分钟周期 HH:mm，跨日带日期；日/周为 MM-dd；悬停标签正确；服务器与客户端时区不同时以服务器为准。
6. 实时更新：看 1m/5m/日线时末根随行情变动，跨分钟/跨整点/跨零点新开一根；玩家下单成交后六个周期末根的收盘与量都更新。
7. 带宽：多人同看不同周期，行情广播体积只多一个 `cd`；离开行情页 45 秒后广播不再带 `cd`。
8. 配置：调小 `barLimit5m` 立刻裁剪；旧 `barLimit=500` 的旧配置映射为 1m 500 根；日/周上限调到 520/208 后正常保存读取。
9. 旧客户端（不传 `period`）连新服务端仍显示 1m 图；新客户端连旧服务端芯片置灰、固定 1m。
10. 存档体积与保存耗时（24 股满额时）。
