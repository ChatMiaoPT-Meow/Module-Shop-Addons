# Module-Shop-Stock 2.0.1 优化与验收

## 范围

本轮按「资产安全 → 两端口径 → 生命周期 → 性能与维护性」优化，不改动主商店。

## 服务端

- 市价/限价平空、限价买卖、开空差额退款均先确认 `credit/debit` 成功，再修改仓位、托管、基金和成交状态。
- 现金退款失败时保留 `escrow`，订单进入 `REFUND_PENDING`；每个行情 tick 重试，成功后回到原定的撤单或过期状态。待退款订单不参与撮合，也不会被历史订单清理。
- 市价平空统一使用 `shortQty - shortLocked`；强平使用最新 `ask`，先解除关联委托，回款成功后才清空头。
- 原始限价先校验价格带，负数、零和超限价不再被 clamp 成有效委托。
- 删除股票按 `bid/ask` 清算多空；任何付款失败都保留对应仓位和股票定义。分红只扣减实际支付成功的基金。
- `trade/cancel/watch/adminAction` 使用持久化 `(UUID, nonce, 请求摘要, 回执)`：同请求重放只回执不执行，同 nonce 不同请求拒绝，中断请求不盲目重放。服务端采用每玩家单调 nonce 高水位与有界回执；客户端单调分配和最终复审见交接文档。写包和榜单增加按玩家限流。
- 存档升级到 dataVersion 3，保存请求回执和退款目标；v1 迁移条件保持为 `<2`，避免 v2 老档被误走 v1 迁移。加载时约束 `shortLocked <= shortQty`。

## 客户端与协议

- 快照在任何字段写入前整体拒绝旧 revision（已有新状态时也拒绝 revision=0）；chart/book 同时校验当前 symbol 和 revision。
- 快照补发 `shortLocked`，所有平空按钮、全平和持仓预填统一使用可用空头。
- 买入看 ask、卖出/开空看 bid、平空看 ask；满仓买入用整笔费用函数反求数量，预估包含手续费。
- 总资产计入空头保证金与浮动盈亏；同一股票的多空持仓分两行显示。
- 页签切换调用旧视图 `cancelInput()`；无快照时低频重试；恢复加载前隐藏的满仓/清仓按钮。
- 回退界面固定普通多头市价单，补心跳、休市/停牌校验、首包列表重建与分页边界；定义变化重建控件时保留数量框焦点和光标。
- 管理台编辑不再清空表单，重建 Screen 后保留字段；管理文本全部翻译化；榜单与审计可滚动。
- K 线尾桶保留，聚合结果按 Chart 对象身份 + factor 缓存，不再每帧分配六组数组。

## 自动化验证

- 新增 7 个纯 Java JUnit 测试类，共 20 项测试：整笔费用、最大可买量、限价校验、空头结算、溢出、双向冻结、退款保留、nonce 重放/冲突/中断/长期保留、K 线尾桶、回包门禁和深度浮亏资产下限。
- 在最后一轮 nonce 高水位改造之前，`./gradlew build -Pmodule_shop_root=E:/心自安然项目/Module-Shop` 通过，20/20 测试成功；`clean build` 在未运行客户端时也曾通过。高水位最新改动尚待重新构建与复审，详见 `交接-2026-11-08.md`。
- 中英文语言文件各 291 键，无缺失对应键。
- 非 ASCII 项目路径下，Gradle 9.2 默认测试 worker 找不到已编译测试类；构建脚本自动改用 JUnit ConsoleLauncher。ASCII 路径继续使用标准 `test` worker。
